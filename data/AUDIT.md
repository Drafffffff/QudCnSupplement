# 静态语料审计

依据游戏 2.0.212.31 官方 `ExampleLanguage` XML，统计 **25,090 个非空、带 ▶ 标记的可本地化字段**。原简中包与增量合计为所有字段提供值，缺失字段为 0。这表示官方导出语料字段可用性达到 100%，**不等于全游戏汉化正确率或覆盖率 100%**。

生成 28 个 `Lang="CN"` 增量 XML，写出 5,479 个字段。补充 Mod 必须在原简中包之后加载。一般只写缺失或更新字段；`Load="Replace"` 集合附带原有兄弟项，避免清空未修改的姓名音节。输入文件哈希、逐字段译文和来源均记录于 JSON。

## 译文与修复

- `manual-translations.json` 用于缺失/英文回退字段，当前有 663 个字段采用人工映射。
- `manual-overrides.json` 修改 263 个既存字段，保存精确文件、节点路径、英文源文和修改前基线，输入变化会立即失败。
- `glossary-visible.json` 补齐静态书籍人名、神名、地名、数学家姓名、种族、拟声词和属性术语。保护变量、样式头、命令、路径、复合派系键和枚举键；不修改玩家动态姓名。
- 已修复缺失变量终止符，例如 `=min.range#max%`、`=bonus%`、`%=year%`；不凋棱镜的嵌套渐变名称保留颜色标签顺序。
- 繁中语料经 OpenCC `t2s` 转简体，未将字符转换误称为人工审校。

## 中文量词与运行时复数问题

真实游戏引擎已证实 `Grammar.Pluralize("打兰")` 返回 `打兰s`。因此不能通过允许 selector 参数中文化来放过此问题。

生成器对已审阅的单参数名词操作改用中文量词字面量。例如：

- `=give= =give.pluralize:dram=` → `=give= 打兰`，保留数量变量。
- `=transfer.things:dram=` → `=transfer= 打兰`，将组合操作拆为数量变量和量词。
- 中文 `pluralize:回合`、`things:单位` 等同类操作也做相同修复。

共修改 113 个字段、117 个操作。`literal-units.json` 定义已审阅词汇；分支选择器和 `pluralize:direct` 等对象语义操作不作名词替换。`unit-operation-audit.json` 逐字段记录操作前后全文、确切移除 token、确切新增数量 token 和中文量词。原 selector 参数白名单已退役，条目为空。

`new-translation-token-audit.json` 检查 5,354 个新/回退字段，43 个字段因上述确切操作发生 token 差异；未批准差异为 0。测试逐字段重建全文并核对 token 多重集合，不能忽略任意变量差异，也不能吞掉数量变量。

## 保留内容与范围限制

所有最终译文共 216 个字段仍含拉丁字母，主要是型号、罗马数字、按键与命令、程序字段、选项枚举键、复合派系/代词标识符、文件名、技术缩写、真实制作人员署名、原始第三方许可证和联系地址。`existing-mixed-latin.json` 现统计**全部最终译文来源**；文件名沿用旧名。分类是可复核清单，不把未识别内容自动认定为合理保留。

`token-warnings.json` 保留完整英文导出与译文 token 的差异记录。它同时包含原包合法中文 selector 参数、中文语法省略、原包结构差异和已审阅的量词操作，不能将其条目数等同于损坏变量数量。分类与确切量词操作审计分别保存。

XML 导出以外的 C# 拼接、程序生成文本、`historyspice` JSON、其他 Mod 文本、未导出字符串、翻译语义和排版不由这份统计证明；必须结合相应模块审计及实机验证。

## 验证与复现

所有生成 XML 可解析、语言标识为 CN、无 ▶ 导出标记。项目测试验证精确语料范围、输入哈希、变量差异、量词修复、动态规则和历史语料。

```sh
.venv/bin/python tools/build_corpus.py
.venv/bin/python -m unittest discover -s tests -v
```

默认使用本项目 `sources/`，不依赖相邻调查目录。构建离线运行，需要 `requirements.txt` 中的 Python 依赖。请编辑人工映射或生成器后重新生成，不直接维护生成 XML。
